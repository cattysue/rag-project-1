## PRD 분석 (PRD Analysis)

### 기능 요구사항 (Functional Requirements)

**FR-1: 질문-답변 챗봇 (핵심)**

- **FR-1.1**: 사용자는 자연어(한국어)로 규정 관련 질문을 입력할 수 있다.
- **FR-1.2**: 챗봇은 입력된 질문을 분석하여 규정 문서에서 관련 내용을 검색하고, 요약된 답변을 제공한다.
- **FR-1.3**: 모든 답변에는 관련 출처(조항 번호, 항목명)가 명시된다. 관련 조항이 여러 개인 경우 모두 표시.
- **FR-1.4**: 유사도 점수 임계값 이하 시 "해당 내용은 규정에 명시되어 있지 않습니다" 안내 (환각 방지). 임계값은 개발 단계에서 샘플 질문 테스트를 통해 결정.
- **FR-1.5**: 브라우저 탭이 열려 있는 동안 이전 질문·답변을 기억하여 연속 질문이 가능. 새로고침 시 초기화.

**FR-2: 문서 관리 (관리자 기능)**

- **FR-2.1**: 관리자는 별도의 관리 페이지에 접속하여 규정 PDF 파일을 업로드할 수 있다.
- **FR-2.2**: 관리 페이지는 단일 비밀번호로 보호된다. 비밀번호는 서버 환경변수(.env)에서 관리.
- **FR-2.3**: PDF 업로드 후 시스템은 자동으로 문서를 분석(임베딩 처리)하여 챗봇에 반영한다.
- **FR-2.4**: 업로드 진행 상태(처리 중 / 완료 / 실패)를 관리자가 확인할 수 있다.
- **FR-2.5**: 기존 규정 파일을 새 파일로 교체할 수 있다.

**FR-3: 웹 인터페이스**

- **FR-3.1**: 링크(URL)만으로 접속 가능한 웹 채팅 화면 제공. 로그인 불필요.
- **FR-3.2**: 채팅 화면 구성 — 메시지 입력창(하단 고정), 대화 내역 표시 영역, 챗봇 이름 "규정이" 표시.
- **FR-3.3**: 답변 내 출처 조항은 구분하여 표시된다. [ASSUMPTION: 별도 색상 또는 인용 블록 스타일]
- **FR-3.4**: PC 브라우저 및 모바일 브라우저 모두에서 정상 동작. 반응형 디자인. 별도 앱 설치 없이 링크만으로 접속 가능.

**총 기능 요구사항: 14개 (FR-1.1~1.5, FR-2.1~2.5, FR-3.1~3.4)**

1. **⚠️ 구체적 UI 스펙 없음**: FR-3.2의 "규정이" 표시 방식, 말풍선 색상, 폰트 크기 등이 문서화되지 않음. 스토리 인수 조건에 "표시된다"고만 명시 — 개발자 해석 의존.

2. **⚠️ 에러 상태 UI 미정의**: 백엔드 API 타임아웃, 네트워크 오류 시 프론트엔드 화면 처리 방식이 에픽/스토리에서 명시적이지 않음 (AR-6은 업로드 폴링만 다룸).

3. **✅ 허용 가능**: 내부 도구(K고 교사 전용)이며, 기본 스타일 적용이 PRD에서 확정(Q2: "별도 로고·색상 테마 없음 → 기본 스타일"). 별도 UX 문서 없어도 구현 가능한 수준의 단순한 UI.
