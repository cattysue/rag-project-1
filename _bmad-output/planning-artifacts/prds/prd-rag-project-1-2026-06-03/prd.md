# 제품 요구사항 문서 (PRD)
## K고 학업성적관리규정 RAG 챗봇 "규정이"

---

## 1. 개요

### 1.1 제품 한 줄 요약
K고 교사들이 학업성적관리규정을 자연어로 질문하면, AI가 규정 문서에서 해당 내용을 찾아 출처와 함께 답변해주는 내부 챗봇 서비스.

### 1.2 배경 및 문제 정의
K고 교사들은 성적 처리 과정에서 학업성적관리규정을 수시로 확인해야 한다. 현재는 PDF 파일을 직접 열어 수동으로 검색해야 하므로:
- 원하는 조항을 찾는 데 시간이 걸린다
- 규정 내용을 잘못 이해하거나 놓치는 경우가 생긴다
- 바쁜 업무 중 빠른 확인이 어렵다

### 1.3 해결 방향
규정 PDF를 AI가 미리 학습하고, 교사가 자연어로 질문하면 관련 조항을 찾아 요약 답변과 함께 원문 출처(조항 번호)를 제공하는 RAG(검색-생성 결합) 방식의 챗봇을 구축한다.

---

## 2. 목표 및 성공 지표

### 2.1 목표
| 목표 | 설명 |
|------|------|
| 규정 검색 시간 단축 | 교사가 원하는 규정 내용을 3회 이내 질문으로 찾을 수 있음 |
| 정확한 출처 제공 | 모든 답변에 관련 조항 번호 또는 항목 명시 |
| 규정 최신화 유지 | 담당자가 새 PDF를 업로드하면 즉시 챗봇에 반영 |
| 멀티플랫폼 접근 | 웹 브라우저 및 스마트폰 앱 모두에서 이용 가능 |

### 2.2 성공 지표
- 교사들이 규정 관련 질문에 평균 30초 이내 답변을 얻음
- 챗봇 답변의 출처 정확도: 담당자 검증 기준 90% 이상
- 규정 파일 업데이트 후 24시간 이내 챗봇에 반영

### 2.3 반성공 지표 (Counter-metrics)
- 답변 실패율(질문을 이해 못 하거나 관련 내용 없음 응답 비율)이 20% 초과 시 품질 개선 필요
- 한 번의 질문으로 원하는 답변을 못 찾아 5회 이상 재질문하는 빈도 모니터링

## 3. 사용자

### 3.1 주 사용자: 학교 교사
- **소속**: K고등학교
- **역할**: 성적 처리, 이의신청 응대, 규정 해석이 필요한 담임·교과 교사
- **기술 수준**: 스마트폰과 웹 브라우저 사용에 익숙하나, IT 전문가는 아님
- **사용 맥락**: 성적 처리 기간, 이의신청 접수 중, 학부모 상담 전 빠른 규정 확인
- **주요 불편**: PDF를 열어 직접 검색하는 과정이 번거롭고 시간이 많이 걸림

### 3.2 관리자: 학교 담당자 [ASSUMPTION: 행정실 담당자 또는 교무 담당 교사]
- **역할**: 규정 파일(PDF) 업로드 및 관리
- **접근**: 별도 관리 화면을 통해 파일 업로드
- **기술 수준**: 파일 업로드 수준의 기본 컴퓨터 활용 가능

## 4. 핵심 기능 요구사항

### FR-1. 질문-답변 챗봇 (핵심)

**FR-1.1** 사용자는 자연어(한국어)로 규정 관련 질문을 입력할 수 있다.

**FR-1.2** 챗봇은 입력된 질문을 분석하여 규정 문서에서 관련 내용을 검색하고, 요약된 답변을 제공한다.

**FR-1.3** 모든 답변에는 관련 출처(조항 번호, 항목명)가 명시된다.
- 예시: "제8조 제2항(성적 이의신청)에 따르면..."
- 관련 조항이 여러 개인 경우 모두 표시

**FR-1.4** 검색된 문서의 관련도가 일정 기준(유사도 점수 임계값) 이하인 경우, AI가 내용을 지어내지 않고 "해당 내용은 규정에 명시되어 있지 않습니다"라고 명확히 안내한다. 임계값은 개발 단계에서 샘플 질문 테스트를 통해 결정한다. (환각 방지)

**FR-1.5** 대화는 브라우저 탭이 열려 있는 동안 이전 질문·답변을 기억하여 연속 질문이 가능하다. 새로고침 시 초기화된다.

---

### FR-2. 문서 관리 (관리자 기능)

**FR-2.1** 관리자는 별도의 관리 페이지에 접속하여 규정 PDF 파일을 업로드할 수 있다.

**FR-2.2** 관리 페이지는 단일 비밀번호로 보호된다. 비밀번호는 서버 환경변수(.env)에서 관리하며, 변경이 필요한 경우(담당자 교체 등) 개발자에게 요청하여 처리한다. 복잡한 계정 관리 시스템은 도입하지 않는다.

**FR-2.3** PDF 업로드 후 시스템은 자동으로 문서를 분석(임베딩 처리)하여 챗봇에 반영한다.

**FR-2.4** 업로드 진행 상태(처리 중 / 완료 / 실패)를 관리자가 확인할 수 있다.

**FR-2.5** 기존 규정 파일을 새 파일로 교체할 수 있다.

---

### FR-3. 웹 인터페이스

**FR-3.1** 링크(URL)만으로 접속 가능한 웹 채팅 화면을 제공한다. 로그인 불필요.

**FR-3.2** 채팅 화면 구성:
- 메시지 입력창 (하단 고정)
- 대화 내역 표시 영역
- 챗봇 이름 "규정이" 표시

**FR-3.3** 답변 내 출처 조항은 구분하여 표시된다. [ASSUMPTION: 별도 색상 또는 인용 블록 스타일]

**FR-3.4** PC 브라우저 및 모바일 브라우저 모두에서 정상 동작한다. 화면 폭에 따라 레이아웃이 자동으로 조절된다(반응형 디자인). 별도 앱 설치 없이 링크만으로 접속 가능하다.

## 5. 비기능 요구사항

### NFR-1. 성능
- 챗봇 답변 생성 시간: 질문 제출 후 10초 이내 (네트워크 환경에 따라 다를 수 있음)
- 동시 사용자: 최대 20명 수준 (학교 내부 도구 특성상 소규모)

### NFR-2. 가용성
- Railway 기반 배포로 인터넷 연결 시 24/7 접근 가능
- [ASSUMPTION] 유지보수 다운타임 허용: 야간 및 주말 짧은 시간

### NFR-3. 보안
- 관리자 페이지는 비밀번호로 접근 제한
- API 키(OpenAI 등)는 환경변수(.env)로 관리, 코드에 직접 노출 금지
- HTTPS 통신 (Railway 기본 제공)
- 규정 문서 내용 외 민감한 개인정보 처리 없음

### NFR-4. 유지보수성
- PDF 교체 시 기술 지식 없이도 관리자가 직접 처리 가능
- 환경변수 변경만으로 OpenAI 모델 버전 업데이트 가능

### NFR-5. 접근성
- 별도 설치나 회원가입 없이 링크만으로 접속
- 한국어 인터페이스

### NFR-6. 검색 품질 검증
- 배포 전 샘플 질문 20개 이상으로 검색 정확도 테스트를 수행한다
- 정답 조항을 올바르게 찾는 비율이 80% 이상일 때 배포한다
- 한국어 법규 텍스트에 대한 임베딩 모델(text-embedding-3-small) 성능을 위 기준으로 검증하며, 기준 미달 시 모델 교체 또는 청킹(문서 분할) 방식을 조정한다

## 6. 기술 스택 및 제약

| 구성요소 | 기술 | 역할 |
|---------|------|------|
| 백엔드 | FastAPI (Python) | API 서버, RAG 처리, 문서 관리 |
| 데이터베이스 | PostgreSQL + pgvector | 규정 내용 및 벡터(임베딩) 저장 |
| 컨테이너 | Docker | 로컬 개발 환경 PostgreSQL 실행 |
| 웹 프론트엔드 | Next.js (React) | 웹 채팅 화면 |
| 웹 (반응형) | Next.js (React) | PC + 모바일 브라우저 모두 지원 |
| AI 모델 | OpenAI GPT-4o | 답변 생성 |
| 임베딩 | OpenAI Embeddings (text-embedding-3-small) | 문서 벡터화 |
| 배포 | Railway | 백엔드 + 웹 프론트엔드 인터넷 배포 |

**기술 결정 사항:**
- OpenAI API를 사용하므로 인터넷 연결 필수
- pgvector 확장으로 PostgreSQL에서 유사도 검색 처리 (별도 벡터 DB 불필요)
- 별도 모바일 앱 없음. Next.js 반응형 웹이 PC·모바일 브라우저 모두 커버

## 7. 사용자 흐름 (핵심 시나리오)

### 시나리오 A: 교사의 규정 질문
1. 교사가 웹 링크 또는 앱을 열어 "규정이" 채팅 화면 접속
2. "1학기 성적 이의신청 기간이 언제야?"라고 입력 후 전송
3. 규정이가 규정 문서에서 관련 내용을 검색
4. "제○조 제○항(성적 이의신청)에 따르면, 이의신청 기간은 ○○입니다."라고 출처와 함께 답변
5. 교사가 후속 질문: "이의신청은 어디에 제출해?"
6. 이전 대화 맥락을 유지하며 연속 답변 제공

### 시나리오 B: 담당자의 규정 파일 업데이트
1. 담당자가 관리자 페이지 URL로 접속
2. 비밀번호 입력 후 관리 화면 진입
3. 새 학업성적관리규정 PDF 파일 업로드
4. 시스템이 자동으로 문서 분석 및 임베딩 처리 (처리 중 상태 표시)
5. 완료 후 "업로드 완료" 확인
6. 이후 챗봇 질문에 새 규정 내용이 반영됨

## 8. 범위 외 (Out of Scope)

이번 버전에 포함하지 않는 기능:
- 사용자 계정 관리 및 로그인 (단, 관리자 페이지는 비밀번호 보호)
- 대화 이력의 서버 저장 및 조회 (세션 내 유지만)
- 여러 학교 / 여러 규정 파일 동시 관리 (단일 학교 단일 파일)
- 알림 기능 (규정 변경 시 교사에게 푸시 알림 등)
- 규정 내용의 직접 편집 기능 (PDF 교체만 가능)
- 다국어 지원 (한국어 전용)
- 사용 통계 / 분석 대시보드
