## 잘 된 점

1. **점진적 패턴 확립**: `get_connection()` 컨텍스트 매니저, `no_db_init` 픽스처, 지연 클라이언트 초기화 등 1-2~1-4에서 확립된 패턴이 이후 모든 스토리에서 일관되게 재사용됨.

2. **PDF 파싱 유연성**: "제○조" 정규식이 PDF 공백 아티팩트를 처리하도록 설계되어 실제 규정 문서 파싱에서 잘 동작.

3. **원자적 파일 교체**: `replace_documents()`의 DELETE + INSERT 단일 트랜잭션으로 중간 상태 없이 안전한 교체 구현.

4. **테스트 커버리지**: 스토리별로 테스트가 쌓이면서 1-6 완료 시점에 57개 테스트 전부 통과.

---

## 어려웠던 점

1. **1-6 코드리뷰 패치 집중**: 프론트엔드 스토리에서 버그가 집중적으로 발견됨. React 폴링 패턴(`useRef`, StrictMode)의 복잡성이 예상보다 높았음.

2. **Python 3.14 호환성**: 초기 `psycopg2-binary` 버전이 Python 3.14에서 동작하지 않아 1-1 완료 후 패치 필요.

3. **테스트 격리**: FastAPI lifespan의 `init_db()` 자동 호출이 테스트 환경에서 DB 연결을 시도해 오류 발생 → `no_db_init` 픽스처로 해결했지만 초기에 혼란.

## 핵심 학습

1. **`load_dotenv()`는 main.py 전담**: 서비스 파일에서 호출하면 테스트 독립성이 깨짐. 환경변수는 `os.getenv()`로 지연 읽기.

2. **pgvector 사용 시 `register_vector(conn)` 필수**: 모든 DB 연결에 반드시 포함.

3. **프론트엔드 폴링 패턴 주의**: React StrictMode에서 `setInterval`은 `useRef`로 관리해야 함. 인플라이트 요청은 `AbortController`로 정리.

4. **FastAPI BackgroundTasks의 상태 관리**: 인메모리 딕셔너리는 단일 인스턴스·단일 관리자 사용 패턴에서만 유효. 멀티 인스턴스 배포 시 외부 상태 저장소 필요.
