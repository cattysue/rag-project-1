# Story 3.2: 검색 품질 검증 및 최종 배포 승인

Status: review

## Story

As a 담당자,
I want 배포된 챗봇이 실제 규정 질문에 정확하게 답변하는지 검증하는 테스트를,
so that 교사들에게 공개하기 전에 챗봇 품질이 기준 이상임을 확인할 수 있다.

## Acceptance Criteria

1. **Given** 배포 환경에서 관리자 페이지를 통해 **When** 규정 PDF 파일을 업로드하면 **Then** 임베딩 처리가 완료되고 "업로드 완료" 상태가 표시된다
2. **Given** 규정 파일 업로드가 완료된 상태에서 **When** 담당자가 샘플 질문 20개 이상을 챗봇에 입력하면 **Then** 각 질문에 대한 답변과 출처 조항이 기록된다
3. **Given** 샘플 테스트 결과를 집계했을 때 **When** 정답 조항을 올바르게 찾은 비율을 계산하면 **Then** 80% 이상인 경우 배포 품질 기준을 통과하고 교사 공개 링크가 확정된다
4. **Given** 정확도가 80% 미만인 경우 **When** 품질 기준 미달이 확인되면 **Then** 유사도 임계값 조정 또는 청킹 방식 수정 후 재테스트를 수행한다

### Task 1 상세: 샘플 질문 25개 영역 구성

Dev Agent는 아래 6개 영역에서 고르게 질문을 구성하되, **각 질문에 예상 정답 조항 힌트를 포함**해야 합니다.

> **중요**: 질문은 교사가 실제로 궁금해할 만한 자연스러운 한국어 질문이어야 합니다.
> "제○조에 대해 알려주세요" 같은 직접 참조 질문이 아닌, 상황 기반 질문을 작성합니다.

**구성 예시 (영역별 4~5개):**

- **지필평가·수행평가 비율 및 반영** (4개): 반영 비율, 평가 방법, 성적 산출 공식 등

- **결시·미응시 처리** (4개): 결석 시 성적 처리, 대체 평가 기준 등
- **부정행위·징계 처리** (4개): 부정행위 유형, 처리 절차, 점수 처리 등
- **성적 공개·통지 절차** (4개): 공개 시기, 방법, 학부모 통지 등
- **전출입 학생·특수 상황** (5개): 전학 온 학생 성적, 유급·보충학습 등

### 품질 미달 시 조치 방법

**정확도가 80% 미만이면** 아래 두 가지 조정 방법을 순서대로 시도합니다.

#### 방법 A: 유사도 임계값 조정 (우선 시도)

**파일:** `backend/services/rag.py`

**찾아야 할 코드 패턴:**
```python
SIMILARITY_THRESHOLD = 0.7  # 또는 유사한 숫자 상수
```
또는 코사인 유사도 필터링 부분:
```python
if score < SIMILARITY_THRESHOLD:
    return "해당 내용은 규정에 명시되어 있지 않습니다"
```

**조정 방향:**
- 정확도 낮음 + 답을 못 찾는 경우 많음 → 임계값 **낮추기** (예: 0.7 → 0.5)
- 정확도 낮음 + 엉뚱한 조항 자주 반환 → 임계값 **높이기** (예: 0.7 → 0.8)

**주의:** 임계값을 너무 낮추면 규정 외 질문에도 아무 조항이나 반환될 수 있습니다.

#### 방법 B: 컨텍스트 청크 수 조정 (방법 A 후에도 미달 시)

**파일:** `backend/services/rag.py`

**찾아야 할 코드 패턴:**
```python
TOP_K = 3  # 또는 유사한 상수 (GPT에 전달할 최상위 청크 수)
```

**조정 방향:**
- TOP_K를 3 → 5로 늘리면 더 많은 관련 조항을 GPT에 전달하여 정확도 향상 가능
- 단, TOP_K가 너무 크면 응답 속도 저하 (10초 이내 NFR-1 유의)

#### 방법 C: 청킹 단위 재검토 (방법 A, B 모두 미달 시)

**파일:** `backend/services/pdf.py`

**현황 파악:**
```python
# 현재 "제○조" 정규식 기반 조항 단위 청킹
# article_number, article_title 추출
```

**문제 상황:**
- 하나의 조항이 너무 길어 여러 내용이 혼재 → 항(①②③) 단위로 더 세분화 고려
- 서문·부칙 청크가 검색에 혼입 → 폴백 청크 필터링 로직 검토

**조정 후 반드시:**
```bash
# 로컬에서 테스트 후 Railway에 재배포
git push  # Railway 자동 재배포 트리거
```
