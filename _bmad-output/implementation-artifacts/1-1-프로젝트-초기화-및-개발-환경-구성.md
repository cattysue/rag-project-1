# Story 1.1: 프로젝트 초기화 및 개발 환경 구성

Status: review

## Story

As a 개발자,
I want 로컬 개발 환경(Next.js, FastAPI, Docker PostgreSQL)이 완전히 구성된 상태를,
so that 이후 모든 개발 작업을 바로 시작할 수 있다.

## Acceptance Criteria

1. **Given** 프로젝트 루트 디렉토리에서 **When** `docker-compose up -d`를 실행하면 **Then** PostgreSQL+pgvector 컨테이너가 정상 시작되고 포트 5432에서 접속 가능하다
2. **Given** Docker PostgreSQL이 실행 중일 때 **When** `cd backend && uvicorn main:app --reload`를 실행하면 **Then** FastAPI 서버가 http://localhost:8000에서 응답하고 `/docs` 페이지가 열린다
3. **Given** FastAPI 서버가 실행 중일 때 **When** `cd frontend && npm run dev`를 실행하면 **Then** Next.js 개발 서버가 http://localhost:3000에서 실행된다
4. **Given** 프로젝트가 초기화되었을 때 **When** `backend/.env.example` 파일을 확인하면 **Then** OPENAI_API_KEY, DATABASE_URL, ADMIN_PASSWORD 세 환경변수가 안내되어 있다
5. **Given** Next.js 앱이 백엔드로 API 요청을 보낼 때 **When** localhost:3000 → localhost:8000으로 요청이 발생하면 **Then** CORS 오류 없이 응답이 반환된다

### docker-compose.yml 상세 스펙

```yaml
version: '3.8'
services:
  db:
    image: pgvector/pgvector:pg15
    environment:
      POSTGRES_USER: raguser
      POSTGRES_PASSWORD: ragpass
      POSTGRES_DB: ragdb
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data

volumes:
  pgdata:
```

- 이미지: `pgvector/pgvector:pg15` (pgvector 확장 포함된 공식 이미지 — 별도 설치 불필요)
- 사용자/비밀번호/DB명은 개발용 고정값 사용 (`raguser` / `ragpass` / `ragdb`)
- DATABASE_URL: `postgresql://raguser:ragpass@localhost:5432/ragdb`

### backend/requirements.txt 패키지 목록


> 버전 고정 이유: Railway 배포 시 재현 가능한 환경 보장. `openai` 1.x는 2.x와 API가 다르므로 버전 고정 필수.

### backend/main.py 상세 스펙

```python
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

app = FastAPI(title="규정이 API")

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:3000"],  # 배포 시 Railway URL 추가 (Story 3.1에서)
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

@app.get("/health")
def health_check():
    return {"status": "ok"}
```

- CORS `allow_origins`에 `http://localhost:3000` 반드시 포함
- `routers/` import는 이 스토리에서 추가하지 않음 (라우터 구현은 Story 1.5, 2.1에서)
- `/health` 엔드포인트만 구현하여 서버 동작 확인용으로 활용

### Project Structure Notes

- 이 스토리는 **모든 후속 스토리의 기반**이 됨. 폴더 구조와 `__init__.py` 파일을 빠뜨리면 Python import 오류 발생.
- `frontend/`는 `create-next-app`이 생성한 구조를 그대로 유지 (임의로 폴더 추가/삭제 금지)
- `backend/` 내 `routers/`, `services/`, `db/`, `tests/` 폴더와 `__init__.py`는 이 스토리에서 반드시 생성 — 내용이 없어도 파일 자체가 있어야 Python 패키지로 인식됨
