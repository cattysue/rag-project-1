## 잘 된 점

1. **RAG 환각 방지 설계**: 시스템 프롬프트 + 유사도 임계값 이중 방어로 규정 외 질문에 명확한 "규정에 명시되어 있지 않습니다" 응답 구현.

2. **컴포넌트 구조 명확성**: `ChatWindow` (상태 관리) / `ChatMessage` (표시) / `ChatInput` (입력) 세 컴포넌트로 역할 분리. 이후 2-3 수정이 단 두 파일만 건드리면 됐음.

3. **Epic 1 기술 부채 즉시 해소**: HNSW 인덱스를 2-1 시작 시 바로 추가. 부채를 다음 에픽으로 넘기지 않음.

4. **2-3 범위 절제**: PC 반응형 레이아웃이 이미 2-2에서 완성되어 있음을 확인하고, 불필요한 재작업 없이 필요한 것만 추가.

## 어려웠던 점

1. **한국어 IME 버그**: 한국어 입력의 특수성 (`isComposing` 이벤트)을 초기 구현에서 놓침. 한국어 특화 프론트엔드 개발 시 반드시 IME 처리를 초기 설계에 포함해야 함.

2. **테스트 실행 순서 의존성**: pytest 실행 순서에 따라 DB 픽스처 충돌 발생. `autouse` 픽스처 범위와 순서를 의식적으로 설계해야 함.

3. **Tailwind CSS v4 + Next.js 16 학습 곡선**: 이전 버전과 설정 방식이 크게 달라 초기에 `tailwind.config.js`를 작성하려다 수정 필요.

## 핵심 학습

1. **한국어 입력 이벤트 처리**: 한국어(CJK) 입력창에는 `onKeyDown`에서 `!e.nativeEvent.isComposing` 체크 필수. 이 코드는 삭제하면 안 됨 (`3-1` 스토리에서도 명시적 주의 사항으로 기록됨).

2. **Tailwind CSS v4는 별도 학습 필요**: `tailwind.config.js` 없음, CSS-first 설정, 유틸리티 클래스명 일부 변경. Next.js 16 + React 19와 함께 사용 시 "최신 가이드" 기준으로 구현해야 함.

3. **시각적 상태 3분류**: RAG 챗봇 메시지는 "사용자 질문 / 봇 답변(출처 있음) / 봇 답변(규정 외)" 세 가지로 분류해 각각 다른 스타일 부여하는 것이 UX상 효과적.

4. **유사도 임계값 설계**: 초기에는 0.5로 설정했으나 Epic 3에서 한국어 어휘 불일치 문제로 반복 조정이 필요했음 → 다음 프로젝트에서는 초기부터 하이브리드 검색 포함 설계 권장 (`[[feedback-korean-rag]]` 참고).
